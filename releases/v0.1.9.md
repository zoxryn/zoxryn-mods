# Zoxryn Mods v0.1.9 — Neon Collection

- Redesigned Overview, My Mods, Installed Mods, Suits & Skins, Discover Mods, Game & Dependencies, Backups & Recovery and Settings, plus a new Unidentified Files page. Original static skyline, purple accents, global search, custom window controls and a details inspector share one design. Appearance settings support glow strength and reduced motion.
- Smart Mod Folders use explicit package metadata, descriptive parent directories and supported loading boundaries across superhero, Police & LSPDFR, vehicle, weapon, map/graphics, ped and general script packages. Support files stay beneath their virtual parents. Separate callout/plugin packages and shared dependency references retain independent identity and ownership.
- Police organization includes core, shared RAGE, callout, plugin, vehicle, uniform/ped and audio sections. Virtual folder/category corrections and custom collections never move installed files.
- Suits & Skins shows explicitly identified or manually confirmed outfits. Generic resource and archive clues stay outside the gallery; all original scan evidence remains accessible through Advanced File Inspector. Labels and grouping never grant safe-management authority.
- Final focused improvements: character/package browsing and expandable outfit components, keyboard-accessible category hints and visible selected labels, clearer detected/management explanations, original category placeholders and bounded explicitly declared local package artwork. Exact known hero loader aliases reference one matching data folder; ambiguous versions stay separate. Supporting DLLs alone do not establish independent nested packages.
- Mod Health Check reports dependency/conflict warnings, incomplete scans, tracked-file problems and recovery issues. Runtime compatibility remains separately unverified. The existing approved, backed-up transaction engine controls supported packages.
- Fixed individual removal of missing custom collection members and file-count undercounting across separate game directories. Canonical ownership keys were not changed.
- Preserved application identity, schema 3 data, archives, settings, backup/recovery protections and the existing cryptographically verified Tauri updater.
- Prepared an explicit release-candidate workflow and isolated signing/publishing coordinator. Production automation remains disabled pending security provisioning, hosted staging and owner approval. Ordinary commits and pull requests do not publish releases.

Detection limits remain: inferred folders do not prove complete package identity; file presence does not prove runtime compatibility. Encrypted/nested RPF payloads, arbitrary AddonPeds registrations, proprietary outfit configurations, shared archive edits and multi-suit bundles cannot be individually toggled unless a supported independent package is verified. No original RPF is edited and no one-click publisher downloads are claimed.

## Verification limits

- The authentic public v0.1.8-to-production-v0.1.9 upgrade in a Windows VM was intentionally skipped with the owner's authorization. No claim is made that this authentic upgrade path was tested. Separate instrumented QA builds exercised signed installation, restart, synthetic-data preservation and failure handling.
- Real GTA V compatibility and gameplay were not tested. Development and file-operation tests used synthetic game directories; the real game and installed application were not changed.
- Unattended production publishing remains disabled. This release is published through a separately authorized manual process.

This installer uses the existing current-user Windows application identity and update trust. In the installed app, open **Settings → Check for Updates**, review the verified offer and choose **Update & Restart** when ready. An update check alone does not download or install the update.
